HW 18-1：完成 Data Hazard 偵測（25 分）
簡介
在實驗中，你使用基於 stall 的方式實作了 WB-to-ID、MEM-to-ID 和 EXE-to-ID 情境的 data hazard 偵測。在這份作業中，你必須確保你的實作正確處理所有 RV32I 指令類型，並通過兩個測試程式。

要求
在 Controller.scala 中完成所有 data hazard 偵測：

is_D_use_rs1 必須涵蓋所有讀取 rs1 的 opcodes（R-type、I-type、B-type、JALR、LOAD、STORE）。
is_D_use_rs2 必須涵蓋所有讀取 rs2 的 opcodes（R-type、B-type、STORE）。

rd =/= 0.U(5.W) 檢查必須出現在所有 overlap 條件中。
實作 control hazard 處理（branch hazard）：

用於 branch misprediction 偵測的 Predict_Miss 信號。
用於 flush IF 和 ID stages 的 Flush_BH 信號。
PC 選擇邏輯（misprediction 時選擇 EXE_T_PC）。

HW 18-2：Performance Counters 8-14 和效能分析 2-4（25 分）
簡介
在 Lab 17-5 中，你實作了 performance counters 1-7。在這份作業中，你要加入 counters 8-14 並實作效能分析指標 2-4。

要求
Performance Counters（14 分）
在 topTest.scala 中加入以下 counters：

#	Counter 名稱	描述	如何偵測
8	Mem Read Stall Cycle Count	因記憶體讀取而 stall 的 cycles	有 load 指令等待時 Stall_MA == 1
9	Mem Write Stall Cycle Count	因記憶體寫入而 stall 的 cycles	有 store 指令等待時 Stall_MA == 1
10	Mem Read Request Count	已執行的 load 指令計數	在 MEM stage 偵測到 Load 類型指令
11	Mem Write Request Count	已執行的 store 指令計數	在 MEM stage 偵測到 Store 類型指令
12	Mem Read Bytes Count	load 指令讀取的總位元組數	每次 load 請求 4 bytes（lw/lh/lb 在 bus 上都占用 4 bytes）
13	Mem Write Bytes Count	store 指令寫入的總位元組數	每次 store 請求 4 bytes（sw/sh/sb 在 bus 上都占用 4 bytes）
14	Committed Instruction Count	完成執行的指令	WB stage 中有效的（非 flush、非 bubble）指令
實作指引：

你需要從 CPU peek 額外的信號來偵測 load/store 指令。考慮 peek MEM 或 WB stage 的 opcode。
對於 counters 12 和 13，無論實際資料寬度為何（lw、lh、lb 在此設計中都在 bus 上傳輸 4 bytes），每次記憶體請求都計 4 bytes。
對於 counter 14，只有當 WB stage 中是有效指令（不是 bubble 或被 flush 的指令）時才計為「已 committed」。
輸出格式： 遵循與 counters 1-7 相同的格式：

println(s"[Mem Read Stall Count           ] ${"%8d".format(Mem_Read_Stall_Count)}")
println(s"[Mem Write Stall Count          ] ${"%8d".format(Mem_Write_Stall_Count)}")
println(s"[Mem Read Request Count         ] ${"%8d".format(Mem_Read_Request_Count)}")
println(s"[Mem Write Request Count        ] ${"%8d".format(Mem_Write_Request_Count)}")
println(s"[Mem Read Bytes Count           ] ${"%8d".format(Mem_Read_Bytes_Count)}")
println(s"[Mem Write Bytes Count          ] ${"%8d".format(Mem_Write_Bytes_Count)}")
println(s"[Committed Inst Count           ] ${"%8d".format(Committed_Inst_Count)}")
效能分析（11 分）
實作以下效能分析指標，印在 performance counters 之後：

#	分析指標	公式
2	Average Mem Read Request Stall Cycle	Mem Read Stall Cycle Count / Mem Read Request Count
3	Average Mem Write Request Stall Cycle	Mem Write Stall Cycle Count / Mem Write Request Count
4	Total Bus Bandwidth Requirement	Mem Read Bytes Count + Mem Write Bytes Count
輸出格式：

println(s"[Avg Mem Read Stall Cycle       ] ${"%8f".format(
  if (Mem_Read_Request_Count > 0)
    Mem_Read_Stall_Count.toFloat / Mem_Read_Request_Count.toFloat
  else 0.0f)}")
println(s"[Avg Mem Write Stall Cycle      ] ${"%8f".format(
  if (Mem_Write_Request_Count > 0)
    Mem_Write_Stall_Count.toFloat / Mem_Write_Request_Count.toFloat
  else 0.0f)}")
println(s"[Total Bus Bandwidth (bytes)    ] ${"%8d".format(
  Mem_Read_Bytes_Count + Mem_Write_Bytes_Count)}")
注意： 處理除以零的情況 —— 如果沒有記憶體讀取或寫入請求，平均 stall cycles 應報告為 0.0。

簡介

要求

使用 Cycle Count / Committed Inst Count 計算的 CPI

Pipeline utilization = Committed Inst Count / Cycle Count

多少百分比的 cycles 是「浪費的」（stalls + flushes）？
